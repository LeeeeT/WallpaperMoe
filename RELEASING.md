# Releasing

Releases are cut locally. `nix run .#release` uses a smaller Nix environment
that excludes the emulator and system image; Gradle reuses its caches between
releases.

## One-time setup

Put a production keystore in your Gradle user properties file
(`~/.gradle/gradle.properties`):

```properties
moe.storeFile=/absolute/path/to/wallpaper-moe.jks
moe.storePassword=...
moe.keyAlias=...
moe.keyPassword=...
```

Release builds never fall back to the Android debug key, and the command
rejects an APK carrying a debug certificate.

You also need `gh auth login`, and Git configured to sign — the release commit
and tag are both signed, and both are verified before anything is pushed.

## Cutting a release

Start from a clean `main` that exactly matches `origin/main`, then pick a
stable semantic-version bump:

```bash
nix run .#release -- patch
# or: minor / major
```

`version.properties` holds the last released version; the command bumps it and
the monotonic Android `versionCode`, runs release lint, builds a
production-signed universal APK, creates a signed `Release vX.Y.Z` commit and
annotated tag, atomically pushes `main` and the tag, then uploads the APK and
its SHA-256 checksum to a **draft** GitHub release with autogenerated notes.

Review the draft and publish it yourself — the command never publishes.

## When it refuses

Nothing is pushed until the version, lint, APK, signing certificate, commit and
tag have all passed locally, so a failure before the push leaves no trace.

- **An unfinished draft exists.** Publish or delete it; the command will not
  bump past a release that was never finished.
- **Interrupted after the push.** Run the same command again. It rebuilds the
  same version and finishes that draft instead of bumping again.
- **`origin` has no `main`.** Push `main` first; the first release needs
  something to fast-forward from.
